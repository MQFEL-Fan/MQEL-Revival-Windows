# Preprod 2026-11-22: heroes pack, friends online, countries, yearly events, competitions

Built and tested in `MQEL-FeatureTest-Preprod` (95 tests pass); not on the
live server yet. Every change below is server-side or a patch the launcher

## All Heroes Pack (bling shop)

A card in the Heroes tab of the bling shop (`bling_shop.HERO_PACK_ID` 900,
not a SpecialPack) unlocks every hero the player doesn't own yet:

- A player starts with one free hero (chosen in the tutorial); the other
  three cost 950 blings each in the game (SKUs 12534/12535/12536/13718,
  `account_state.HERO_SKUS`).
- Price = missing heroes x 950 x **70 %**, rounded to 50
  (`balance.hero_pack_price`): 3 missing 2,000 instead of 2,850 (saves
  850); 2 missing 1,350 instead of 1,900. With only one hero missing the
  card is hidden (buy it in the game). The free hero doesn't matter, only
  which heroes are still missing.
- A trial hero (free trial) counts as missing; buying the pack keeps its
  level and gear (`AccountState._grant_hero`, shared with the normal hero
  purchase). Expired trial heroes come back too.
- Admin: Economy -> "All Heroes Pack (bling shop)" -> percent (0 = not
  offered). Only with the bling economy enabled, like the other packs.
- The heroes arrive at once (HeroUnlocked notifications); ledger tag
  "bling shop", tracking SpecialPackPurchased with SpecialPackId 900.

## Online status of friends

A green (online) or red (offline) dot at the top left of each friend's
picture in the friend list (lobby, friends button).

- The client's friend data (`AccountSummaryForFriend`) has no online field
  and the client drops fields it doesn't know, so the friend list asks the
  server: `GET /friends/online?a=<own AccountId>` on port 8081
  (`presence.friends_online`). Answer `{"<friend id>": true|false}` for the
  friends of that account only, and only to the IP of that player's own
  game connection (or the server PC itself); others get 403.
- Online = the friend's game sent a request in the last 3 minutes
  (`presence.ONLINE_S`; the game sends KeepAlive/Track about once a minute).
- UI patch 14 (`ui_patches.py`, friendNotificationsModule.js): asks
  `http://127.0.0.1:8081` first (the server PC), then
  `http://<MQEL_PUBLIC_HOST>:8081`; refreshes every 30 s while the list is
  open. The address is built into the UI patch, so a new public host needs
  a server restart (new GameUI version).
- Fix (same day): the dot of the next friend covered "View Profile" in the
  player menu of the friend above. The menu
  (`#module-player-interaction-container`) is absolutely positioned without
  a z-index; the patch now gives it z-index 30 and the dot z-index 2.

## Country flags (new players were all German)

- Cause: the country database `server/data/geoip-country.csv.gz` was missing
  on both servers, so `geoip.country()` found nothing and new accounts kept
  the template's "DE". Downloaded with `python tools/update_geoip.py`
  (db-ip.com IP to Country Lite, CC BY 4.0, 2026-11 file, 4.6 MB). Run it
  again every few months; the server reads it at start.
- New: the country now follows the IP the player connects from on every
  request (`Players.get` -> `AccountState.set_country`), not only at account
  creation. Existing "DE" players get their real flag at their next login;
  clan member lists, friends and leaderboards show it. Local/LAN IPs (the
  server PC) change nothing.
- Lookups are local; no IP leaves the server.

## Yearly in-game events (`server/community_events.py`)

The game data has boost events and a loot event (CommunityEventSettings, in
`settings2.bin`); Ubisoft set their dates by hand. They now repeat every
year by themselves (UTC):

| When | Event |
|---|---|
| Every month, third Friday 17:00 to Monday 05:00 | Boost weekend, rotating: Jan gold, Feb life force, Mar XP, Apr magic find, May bling mine, Jun material mines, Jul gold, Aug life force, Sep XP, Oct magic find, Nov bling mine |
| December, third weekend | Everything x2 (all six boosts, like February 2015) |
| Jul 1 10:00 to Sep 25 22:00 | "More Materials" (original 2014 dates): material drops from player castles and gear bonus materials x2 |
| Day 1-7 of every month | Hero free trial, rotating (free_trials.py, unchanged) |
| Oct 20 - Nov 3, Dec 15-30, Dec 31 - Jan 2, Feb 10-16, Easter +- 7 days | Halloween, Christmas, New Year, Valentine's Day, Easter: lobby look, seasonal shop items, Halloween pack and castles (patcher.EVENTS, unchanged) |

Boost effects (+100 % each, from the game data): gold/life force from
attacks and from mines, XP, magic find (better item quality), bling mine
production, material mines twice as fast. Boost potions add on top.

How it reaches the players: the launcher's CommunityEventSettings package
(`patcher.settings2`) gets the event's dates in
CommunityEventBoostSettings/CommunityEventLootSettings; the version gets
`.E<yyyymmdd><boost id or 00>` and `.M<year>` (e.g.
`104956.Christmas.E2026121800.L...`), so players download it at the next
launcher start. The server applies the same calendar
(`attack_factors`, `mine_factor`, `material_period_factor`,
`more_materials`). Test a boost now: `game_server.py --boost-event 21`
(21 gold ... 26 material mines, 0 = all).

Calendar for a year: `python -c "import sys; sys.path.insert(0,'server'); import community_events as c; [print(*x) for x in c.calendar(2027)]"`.

## Competitions stuck on loading (and the 2014 UI scripts)

- Cause: the UI scripts in `client/GameData/Data/UI/Js` are the **May 2014**
  UI, but the game and the players' Steam install have the **July 2015** UI
  (GameUI 280139). `ui_patches.py` patched the 2014 copies and the patcher
  shipped them to the players as whole files. The 2014 competition popup
  asks `ChallengeController.getChallenge`, which the 2015 game never answers:
  spinner forever, and the server never saw a `GetUbisoftCompetitionInfo`.
- Fix (UI patch 15): the originals of all patched scripts are now the 2015
  files from `0.36.1.34.0_280139_GameUI.7z` in `server/data/steam/Data/UI`
  (CastleCompetitionPopUpModule.js, forgeModule.js, hyperquest.extensions.js,
  playerInteractionModule.js, lobbyWalletModule.js,
  friendNotificationsModule.js). The forge note (3.) and "Attack Castle"
  (6.) patches apply again (their anchors were missing in the 2014 files).
  The 2015 wallet script already formats the bling counter, so 11. keeps
  only the count-up removal.
- Players get the fixed scripts with the next GameUI version (launcher
  start). The popup then loads `GetUbisoftCompetitionInfo` (already
  implemented: ranking, rewards, time left).

## Client comparison with `ubisoft-mighty-quest-.zip`

Extracted to `mqel/ubisoft-mighty-quest-extracted/`: the five 0.36.1.34.0
archives (GameData 104956, GameUI 280139, Game 280139, PublicLauncher
276072, GameplayToolbox main.348.1), the same builds the project started
from. Compared file by file with `client/` (`_temp60/cmp_ui.py`):

- **No unreleased content.** Heroes, special packs (75), creatures, traps,
  rooms, abilities, buildings, Ubisoft castles (96), achievements, avatars
  and SKUs listed in the 2015 tables all exist in `client/` (which has more:
  254 creatures, 573 abilities, 6,460 SKUs, the level-60 changes).
  CommunityEventSettings are byte-identical.
- **New in the zip:**
  - 2015 UI (see above; the fix uses it).
  - `GameplaySettings/CSV/Dim*.csv`: Ubisoft's analytics tables (events,
    packs, heroes, castles, SKUs ...). DimCommunityEvent.csv shows the
    original boost weekend (2015-02-20 17:00 to 02-23 05:00). Copied into
    `client/GameData/Data/GameplaySettings/CSV` (reference only, the game
    doesn't read them).
  - `Bigfiles/PC/P4/**/*.bfdebugpc` and `*.bfnamepc` (102 files, 201 MB):
    debug name tables of the packed bigfiles. Not copied; they could help
    to find texture names inside the bigfiles (e.g. room card pictures).
  - `MightyQuest_release.exe`, `MightyQuestWorker*.exe`, the launcher's
    installer folder (EULAs, DirectX/VC redistributables): nothing new for
    the game.
- Nothing in `client/` was removed or replaced.
